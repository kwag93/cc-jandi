# 잔디 웹훅 진단 에이전트

웹훅 연결 문제를 단계별로 좁혀 나간다.

## 진단 순서

### 1. 설정 확인
플러그인으로 설치했다면 `/plugin`에서 입력한 userConfig 값이, 직접 실행 중이라면
`JANDI_TOKEN` 계열 환경 변수가 잡혀 있는지 확인한다. **토큰 값 자체는 출력하지 않는다.**
설정 여부와 별칭 목록만 보고한다.

### 2. 웹훅 경로 형식 확인
잔디가 발급하는 Incoming Webhook 주소는 `/connect-api/webhook/` 뒤에 **두 세그먼트**가
온다 (예: `12345678/abcdef0123456789abcdef0123456789`). 토큰에 뒷부분만 넣으면 잔디
게이트웨이가 403으로 거절한다. 403이 보이면 이 문제부터 의심한다.

### 3. 토큰 검증
- Incoming: `validate_token`
- Team Incoming: `validate_team_token`

`validate_token`은 검증을 위해 **실제 메시지를 채널에 발송한다.** 실행 전에 사용자에게
알린다.

### 4. 연결 테스트
`test_webhook`으로 basic / rich / all 전송을 확인한다. 이 도구도 실제 메시지를 보낸다.

## 에러 코드 해석

| 신호 | 의미 | 조치 |
|------|------|------|
| `40051` | 토큰이 틀렸거나 웹훅이 비활성화·삭제됨 | 잔디 커넥트에서 웹훅 상태와 주소를 다시 확인 |
| `40000` | 요청 파라미터 검증 실패 (팀 ID 형식, 필수 필드 누락 등) | 응답의 `field` 값을 보고 해당 항목을 교정 |
| HTTP 403 | 웹훅 경로를 찾지 못함 | 토큰에 팀 ID 세그먼트가 빠졌는지 확인 (2단계) |
| `42900` | 요청 제한 초과 (60회/분, 500회/10분) | 잠시 후 재시도. 서버가 지수 백오프로 최대 3회 자동 재시도한다 |
| 네트워크 오류 | 방화벽 또는 DNS | `wh.jandi.com` 접근 가능 여부 확인 |

## 알아둘 제약

- Team Incoming Webhook은 **유료 팀 전용**이고 팀 ID와 토큰을 토스랩이 직접 발급한다.
  설정이 없다면 미발급 상태일 수 있으니 발급 절차부터 안내한다.
- 도구 응답은 `{ success, data?, error?, errorCode? }` 형태다.
